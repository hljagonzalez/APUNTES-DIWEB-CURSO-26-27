📋 Introducción a la Maquetación Web

¿Qué es la Maquetación Web?

Cuando comenzamos un proyecto web, debemos pensar en el sitio como una obra arquitectónica. Al igual que un arquitecto no construye un edificio sin planos, nosotros no desarrollamos un sitio web sin una maqueta.

Proceso de Maquetación

El primer paso es hablar con el cliente para obtener los datos suficientes y realizar los bocetos preliminares. Debemos saber y pensar previamente:

✅ Cuáles son los elementos que contendrá cada página
✅ Cómo irán colocados esos elementos dentro de las páginas
✅ El espacio disponible (ventana del navegador, responsive design)

Diseño Escalonado

Los bocetos deben reflejar la interactividad y funcionalidad del sitio web. El resultado de la maquetación será un prototipo.

✏️ Sketches - Bocetos Iniciales

Definición

El sketch es el primer boceto que realizamos para un proyecto digital que queremos crear. Son nuestros primeros trazos, generalmente sobre una hoja de papel (aunque también pueden ser digitales).

Características Principales

🎨 Calidad

Bosquejo estático en baja calidad

📝 Medio

Generalmente sobre papel

⚡ Rapidez

Se crean rápidamente para explorar ideas

✏️ Flexibilidad

Fácil de modificar y descartar

¿Qué debe reflejar un Sketch?

Un sketch debe responder a las siguientes preguntas sobre las ideas generales del proyecto:

  • Elementos Característicos: ¿Dónde pondremos el logo? ¿Dónde irán los elementos destacados?
  • Navegación: ¿Dónde estará la zona de navegación? ¿Menú superior? ¿Lateral? ¿Footer?
  • Ayuda y Soporte: ¿Dónde se cargan los sistemas de ayuda para usuarios?
  • Redes Sociales: ¿Se agregarán servicios de redes sociales? ¿Dónde se ubicarán?
  • Áreas de Contenido: ¿Qué áreas de contenidos y servicios queremos presentar?

Buenas Prácticas

✅ Añadir notas en los laterales para explicar decisiones de diseño
✅ Hacer múltiples versiones para explorar diferentes opciones
✅ No preocuparse por la estética - es solo para explorar ideas
✅ Enfocarse en la estructura y distribución general

📐 Wireframes - Esquemas Estructurales

Definición

El wireframe es una representación esquemática de la interfaz que define la estructura, jerarquía y funcionalidad de cada página, sin incluir elementos visuales finales.

Características Principales

🔲 Escala de grises

Sin colores finales

📐 Estructura

Enfocado en layout y organización

📦 Placeholders

Cajas grises para imágenes

🎯 Funcionalidad

Define elementos interactivos

¿Qué NO incluye un Wireframe?

❌ Colores finales
❌ Imágenes reales
❌ Tipografías específicas
❌ Iconografía detallada
❌ Textos definitivos (usan Lorem Ipsum)

¿Qué SÍ incluye un Wireframe?

✅ Estructura de la página (header, main, aside, footer)
✅ Jerarquía de contenidos (títulos, subtítulos, párrafos)
✅ Ubicación de elementos (botones, formularios, imágenes)
✅ Tamaño relativo de los elementos
✅ Zonas interactivas (enlaces, botones, campos)
✅ Sistema de navegación (menús, breadcrumbs)
✅ Grid y alineaciones básicas

🎨 Mockups - Maquetas Visuales

Definición

El mockup es una composición gráfica completa que utiliza el wireframe como plantilla e introduce todos los elementos gráficos y visuales finales.

Características Principales

🎨 Alta fidelidad visual

Diseño prácticamente final

🖼️ Elementos reales

Imágenes, iconos, ilustraciones

🎨 Paleta de colores

Colores definitivos del brand

🔤 Tipografía final

Fuentes específicas del proyecto

¿Qué incluye un Mockup?

1. Contenidos

  • Textos dummy (Lorem Ipsum) o contenido real borrador
  • Estructura de información definida
  • Jerarquía visual clara

2. Paleta de Colores

  • Colores primarios y secundarios
  • Colores de acento
  • Fondos, textos, botones
  • Estados (hover, active, disabled)

3. Tipografía

  • Fuentes específicas (ej: Montserrat, Poppins)
  • Tamaños y pesos definidos
  • Jerarquía tipográfica clara
  • Line-height y letter-spacing

4. Iconografía

  • Icons específicos (Font Awesome, Material Icons, custom)
  • Estilo consistente (outlined, filled, etc.)
  • Tamaños apropiados

5. Imágenes

  • Fotografías reales o de stock
  • Ilustraciones custom
  • Tamaño y resolución correctos

Diferencias Clave: Wireframe vs Mockup

Aspecto Wireframe Mockup
Fidelidad Media Alta
Color Escala de grises Paleta completa
Imágenes Placeholders Imágenes reales/finales
Tipografía Genérica Específica del brand
Objetivo Estructura y layout Aspecto visual final
Tiempo Rápido Más detallado
Enfoque Funcionalidad Diseño y estética

Implementación en Figma

1. Partir del Wireframe

Duplica tu wireframe y empieza a añadir:

  • Colores del Design System
  • Tipografías finales
  • Componentes visuales

2. Aplicar Design System

Si ya tienes un Design System creado:

  • Usa los componentes definidos
  • Aplica los color styles
  • Utiliza los text styles
  • Incorpora los effect styles (sombras)

3. Añadir Contenido Visual

Imágenes:
• Unsplash Plugin para fotos stock
• Storyset para ilustraciones
• Iconify para iconos

Recursos:
• Elementos UI de librerías
• Componentes de comunidad de Figma
• Assets propios del proyecto

4. Detalles Finales

✨ Sombras y efectos: Drop shadow: 0 2px 8px rgba(0,0,0,0.1) ✨ Espaciados consistentes: • Usa múltiplos de 8px (sistema 8-point) • Auto Layout con spacing definido ✨ Estados interactivos: • Hover effects • Active states • Disabled states

Consideraciones Importantes

⚠️ Mockup NO es Prototipo

❌ El mockup es estático
✅ El prototipo es interactivo

Un mockup muestra el aspecto visual, pero no la funcionalidad. Para testear interacciones necesitamos un prototipo.
💡 Algunos autores no usan Mockups

Algunos diseñadores prefieren:
• Ir directo de wireframe a prototipo en blanco y negro
• Separar totalmente la guía de estilos de las maquetas
• Trabajar con componentes desde el principio

La decisión es del diseñador o el equipo, según metodología, expectativas del cliente, tiempo disponible y complejidad del proyecto.

🖱️ Prototipos Interactivos

Definición

Un prototipo es una representación limitada de un sitio web que permite a las partes (clientes y desarrolladores) explorar y probar su uso de manera interactiva.

Características Principales

🖱️ Navegables

Se puede hacer clic y navegar

🧪 Testables

Permiten pruebas de usabilidad

🎯 Evalúan UX

Identifican problemas de experiencia

🤝 Involucran

Cliente ve y "usa" el producto

Tipos de Prototipos

1. Prototipo de Baja Fidelidad

Base: Wireframes en blanco y negro

Características:
• Interacciones básicas
• Sin animaciones complejas
• Enfocado en flujo y estructura
• Rápido de crear y modificar

Cuándo usar:
• Fases tempranas del proyecto
• Validar estructura y flujo
• Testing rápido de conceptos

2. Prototipo de Alta Fidelidad

Base: Mockups con diseño completo

Características:
• Interacciones complejas
• Animaciones y transiciones
• Micro-interacciones
• Aspecto casi final

Cuándo usar:
• Fases finales antes de desarrollo
• Presentaciones a stakeholders
• Testing exhaustivo de UX
• Documentación para desarrolladores

Implementación en Figma - Modo Prototype

Crear Conexiones

  1. Selecciona un frame con el diseño
  2. Cambia al panel Prototype (panel derecho)
  3. Click en el elemento interactivo (botón, link)
  4. Arrastra el círculo azul hasta el frame destino
  5. Se crea una flecha de conexión

Configurar la Interacción

Tipo Opciones
Trigger (Disparador) On Click, On Hover, On Drag, On Key, After Delay, Mouse Enter/Leave
Action (Acción) Navigate to, Open overlay, Swap with, Back, Close overlay, Open URL
Animation Instant, Dissolve, Smart Animate, Move In/Out, Push, Slide In/Out
Easing Linear, Ease In/Out, Custom cubic-bezier
Duration 300ms (rápido), 500ms (estándar), 800ms (lento)

Smart Animate

La función Smart Animate de Figma es muy potente:

Funcionamiento:
• Detecta elementos similares entre frames
• Anima automáticamente posición, tamaño, rotación
• Crea transiciones fluidas

Requisitos:
• Elementos deben tener el mismo nombre en ambos frames
• Funciona con capas y componentes
Ejemplo de Smart Animate: Frame 1: Rectangle "box" x: 0, y: 0, width: 100 Frame 2: Rectangle "box" x: 200, y: 100, width: 200 → Smart Animate los transforma fluidamente

Overlays (Modales)

Para crear popups y modales:

  1. Crea el frame del modal
  2. En la conexión, selecciona Open overlay
  3. Configura:
    • Position: Center, Top, Bottom, Manual
    • Background: Dimmed o None
    • Close when clicking outside: Yes/No

Scroll

Para áreas scrollables:

  1. Contenedor: Frame padre con tamaño fijo
  2. Contenido: Frame hijo más grande
  3. Configurar:
    • Clip content: ✓
    • Prototipo → Overflow behavior: Vertical/Horizontal scrolling

Testear el Prototipo

Modo Presentación

  • Play button (▶️) esquina superior derecha
  • O presiona: Shift + Spacebar
  • Navega: Como lo haría un usuario

Compartir para Testing

  1. Share button → Presentación en prototype mode
  2. Copy link
  3. Configuración:
    • Anyone with link / Specific people
    • Can view prototype
    • Show hotspot hints: Yes/No
    • Starting frame

Para el Equipo

  • Validación temprana de conceptos

📄 Plantillas de Diseño

Definición

Una plantilla web es un conjunto de documentos web prediseñados que se pueden utilizar para insertar contenido e imágenes y así desarrollar la interfaz del sitio web.

Ventajas y Desventajas

✅ Ventajas

  • Ahorro de tiempo considerable
  • Reducción de costes
  • Código probado y funcional
  • Responsive design
  • Compatibilidad navegadores

❌ Desventajas

  • Limitaciones de personalización
  • Código genérico
  • Menos exclusividad
  • Curva de aprendizaje
  • Problemas con actualizaciones

¿Cuándo usar plantillas?

✅ Usar plantillas cuando:

• Presupuesto limitado
• Tiempo de entrega ajustado
• Proyecto pequeño o mediano
• Cliente valora funcionalidad sobre diseño único
• Prototipo o MVP (Minimum Viable Product)
• Sitio web estándar (blog, portfolio, landing page)
❌ NO usar plantillas cuando:

• Brand muy específico que requiere diseño único
• Funcionalidades muy específicas o complejas
• Cliente paga por diseño custom exclusivo
• Proyecto de gran escala empresarial
• Se requiere diferenciación competitiva fuerte

Estructura Típica de una Plantilla

plantilla/ ├── index.html (Página principal) ├── about.html (Páginas secundarias) ├── contact.html ├── assets/ (Recursos) │ ├── css/ │ │ ├── main.css │ │ └── responsive.css │ ├── js/ │ │ ├── main.js │ │ └── plugins.js │ ├── images/ │ │ ├── hero.jpg │ │ ├── logo.png │ │ └── ... │ ├── fonts/ │ └── icons/ ├── LICENSE.txt (Licencia de uso) └── README.md (Instrucciones)

Proceso de Personalización

1. Localizar Archivos

  • Identifica todos los archivos incluidos (HTML, CSS, JS, assets)
  • Comprende la estructura de carpetas
  • Lee el README si existe

2. Examinar la Estructura

  • Abre con un editor de código (VS Code, Sublime Text)
  • Analiza el HTML (estructura semántica, clases e IDs, secciones a modificar)
  • Revisa el CSS (variables, clases principales, media queries)
  • Usa el inspector del navegador (F12)

3. Editar Contenido de Texto

<!-- Antes --> <h1>Amazing Business Template</h1> <p>This is a sample template for your business</p> <!-- Después --> <h1>Mi Empresa de Software</h1> <p>Desarrollamos soluciones tecnológicas innovadoras</p>

4. Personalizar Imágenes

⚠️ Importante: Mantener el mismo tamaño que las imágenes originales para no romper el diseño.

Proceso:

  1. Identifica las dimensiones de la imagen original
  2. Prepara tu imagen en el mismo tamaño
  3. Usa el mismo nombre de archivo (o actualiza el HTML/CSS)

5. Quitar Elementos No Deseados

⚠️ ¡Con cuidado! Eliminar código puede romper funcionalidades.

Proceso seguro:
1. Comenta el código primero en lugar de eliminarlo
2. Prueba que todo funciona
3. Si está OK, elimina definitivamente
<!-- Comentar HTML --> <!-- <section class="testimonials"> ...contenido no deseado... </section> --> /* Comentar CSS */ /* .testimonials { display: flex; ... } */

6. Modificar CSS

Aunque no es recomendable modificar mucho las CSS (puede romper responsive), hay cambios seguros.

Cambios seguros:

/* Colores */ :root { --primary-color: #3498db; /* Azul original */ --secondary-color: #2ecc71; /* Verde original */ } /* Cambiar a tus colores */ :root { --primary-color: #FF6B6B; /* Tu rojo */ --secondary-color: #4ECDC4; /* Tu turquesa */ } /* Tipografía */ body { font-family: 'Open Sans', sans-serif; } /* Cambiar a */ body { font-family: 'Poppins', sans-serif; }

Cambios riesgosos:

  • Modificar el grid system
  • Cambiar media queries sin testing
  • Alterar z-index sin entender la estructura
  • Modificar positioning (relative, absolute, fixed)

De Plantilla a Proyecto Custom

Flujo de Trabajo Recomendado

  1. Analizar la plantilla en Figma PRIMERO
    • Importa capturas de pantalla
    • Marca áreas a personalizar
    • Diseña los cambios visualmente
  2. Crear un Design System de tu marca
    • Colores
    • Tipografías
    • Componentes
  3. Aplicar cambios en código
    • Siguiendo el diseño de Figma
    • Testing constante
  4. Optimizar
    • Eliminar código no usado
    • Minificar CSS/JS
    • Optimizar imágenes
💡 Ventajas de Diseñar en Figma Antes

Incluso si vas a usar una plantilla, diseñar en Figma primero tiene ventajas:

✅ Visualización clara de cambios antes de codificar
✅ Aprobación del cliente antes de tocar código
✅ Mejor planificación de personalizaciones
✅ Documentación visual para desarrollo
✅ Consistencia en los cambios aplicados

🎯 Conclusiones y Buenas Prácticas

Resumen del Proceso Completo

1. KICK-OFF CON CLIENTE └─> Reunión, brief, requisitos 2. SKETCH (Bocetos) └─> Papel, ideas rápidas, múltiples opciones 3. WIREFRAME (Estructura) └─> Figma, escala de grises, layout definido 4. MOCKUP (Diseño visual) └─> Figma, colores, tipografías, imágenes 5. PROTOTIPO (Interactividad) └─> Figma prototype mode, testing 6. DESARROLLO └─> Código (puede usar plantilla) 7. TESTING Y AJUSTES └─> QA, correcciones 8. LANZAMIENTO └─> Deploy, monitoreo

Adaptación según el Proyecto

Proyecto Pequeño / Landing Page

SKETCH → MOCKUP → PLANTILLA HTML5 (Rápido, económico)

Proyecto Mediano / Sitio Corporativo

WIREFRAME → MOCKUP → PROTOTIPO → DESARROLLO (Proceso completo)

Proyecto Grande / Plataforma Web

RESEARCH → SKETCHES → WIREFRAMES → DESIGN SYSTEM → MOCKUPS → PROTOTIPOS → DESARROLLO ITERATIVO (Proceso exhaustivo)

Errores Comunes a Evitar

❌ Saltar la fase de wireframe - Ir directo a mockup con colores puede ser problemático

❌ No testear el prototipo con usuarios - Desperdicias su mayor ventaja

❌ Modificar plantillas sin entenderlas - Puede romper funcionalidades

❌ No documentar decisiones - Dificulta mantenimiento futuro

❌ Ignorar responsive - Diseñar solo para desktop es un error crítico

❌ No involucrar al cliente en el proceso - Sorpresas al final = problemas

Checklist Final

✅ Sketch → Wireframe

  • Cliente aprobó la estructura general
  • Definidas todas las páginas principales
  • Clarificados los flujos de usuario

✅ Wireframe → Mockup

  • Layout validado y aprobado
  • Jerarquía de contenidos clara
  • Design System listo para aplicar

✅ Mockup → Prototipo

  • Diseño visual aprobado
  • Todos los assets preparados
  • Estados interactivos definidos

✅ Prototipo → Desarrollo

  • Testing de UX completado
  • Feedback incorporado
  • Documentación para devs lista

📚 Ejercicios Prácticos

Ejercicio 1: Del Sketch al Mockup
Elige un tipo de web (e-commerce, blog, portfolio) y:
1. Crea 3 sketches diferentes en papel
2. Elige uno y conviértelo en wireframe en Figma
3. Transforma ese wireframe en mockup completo
Ejercicio 2: Prototipo Interactivo
Toma el mockup del ejercicio 1 y:
1. Crea al menos 5 pantallas conectadas
2. Añade 3 tipos de interacciones diferentes
3. Incluye al menos un overlay/modal
4. Testea con 3 personas y recoge feedback
Ejercicio 3: Personalización de Plantilla
1. Descarga una plantilla de HTML5 UP
2. Analiza su estructura (HTML, CSS, JS)
3. Personalízala para un negocio ficticio
4. Documenta los cambios realizados
💡 Recuerda: El proceso de diseño es iterativo. No tengas miedo de volver atrás y ajustar según el feedback. La flexibilidad es clave para un buen resultado final.
